# ML-07 — intersample peak screening for private offline A/B

This is a **read-only, CPU-only, synthetic-test-backed technical diagnostic**. It does **not** judge mixes, listening preference, perceived loudness or compliance with ITU-R BS.1770. There is no external dependency, background worker, audio upload, stem model or new VPS service.

## Why it exists

A PCM16 peak meter checks only stored discrete samples. A signal with two adjacent samples below 0 dBFS may overshoot between samples during DAC/playback reconstruction. This standalone command offers a **adaptive 4×→8×, sixteen-tap Blackman-windowed sinc estimate** as one additional risk screen. It is a finite approximation, not a calibrated true-peak meter. Warnings need corroboration on a reference meter and/or human audition; absence of a warning is not proof of clipping-free playback.

## Run locally (files never leave the machine)

```bash
python3 -m mixlab.quality.intersample PRIVATE_BASELINE.wav PRIVATE_CANDIDATE.wav
python3 -m mixlab.quality.intersample PRIVATE_BASELINE.wav PRIVATE_CANDIDATE.wav --fail-on-risk
```

Outputs only anonymous JSON: `baseline`, `candidate-1`, sample rate, channels, frame count, sampled peak in dBFS, interpolated peak **estimate** in dBFS, number of estimated fractional over occurrences, plus separate `full_scale_pcm_risk`, `high_frequency_near_ceiling_ambiguity_risk`, `edge_interpolation_ambiguity_risk` and `technical_review_required` flags. No track IDs, filenames, source paths, raw frames, hashes or listening verdicts. `--fail-on-risk` returns exit 2 if **either** baseline or any candidate has an estimated fractional over, a PCM16 sample at either signed rail, unresolved near-ceiling sign-reversal ambiguity, hot unscreened playback boundaries, or fewer than sixteen frames (the screen cannot run). A warning is not proof of actual clipping. Invalid arguments exit 2; unreadable/malformed sources exit 3 with pathless diagnostics. `--help` is non-mutating.

## Resource and input contract

* PCM16 uncompressed mono/stereo WAV, 8–96 kHz, one baseline plus 1–3 candidates.
* Strictly equal channel count, sample rate and frame count are required **before reading PCM**, and the same inode cannot appear twice in the group.
* Per-source file bound 32 MiB and 2,000,000 frames; aggregate group bound 8,000,000 frames; at most 4 file descriptors, <=4096 input frames per read and sixteen-frame interpolation ring. Processing is linear in frames and deliberately CPU-intensive; schedule under normal offline admission only.
* Physical regular-file checks, final-component symlink refusal, full declared-frame reads, post-read descriptor identity/mtime/ctime/size checks **and path-to-descriptor identity verification for every participant after all scans**; source bytes are never modified. These checks are not a hostile-filesystem security sandbox or full RIFF canonicalization. For stronger source/header guarantees use the separately scoped ML-07 single-FD/neutral-container preflight.
* With fewer than sixteen frames, `screen_evaluable=false` and `technical_review_required=true`. The first seven/final eight samples do not have enough two-sided context for interpolation even in longer files; `edge_interpolation_ambiguity_risk=true` when either first eight or final eight input frames contain a >=95%-FS sample. This conservative edge warning does not claim a true-peak over or necessarily an audible pop.
* Even the longer 16-tap filter can **miss** actual between-sample peaks in near-Nyquist bandlimited sine waves. A conservative, channel-local guard treats a fast sign reversal with one sample >=95% FS and the other >=55% FS as an **uncertain near-ceiling case** rather than as `intersample_over_risk=true`. This signal heuristic is not spectral classification; it may warn for legitimate percussive content and it cannot catch all underestimates. It counts only events, never positions or PCM values. `technical_review_required` combines estimated overs, exact PCM16 rail hits, fast-crossing ambiguity, near-full-scale edge uncertainty and insufficient (<16) frames. This allows a fail-closed CI risk gate without inventing false 'measured overs'.
* The filter's frequency response is not equivalent to a formally calibrated true-peak meter. The number of estimated overs is a proxy count of fractional phases/channels, **not a count of independent audible clips**. Do not label the estimate 'dBTP' or use it to rank A/B candidates.

## Differential synthetic false-negative regression (near Nyquist)

A full-scale-related 0.4 cycles/sample sinusoid with **analytic amplitude 34,200 / 32,768 = 1.0437 FS** can be sampled at phase zero to all legal PCM16 values (peak **32,526**, less than the clip ceiling). Even with the 16-tap FIR, reconstructed 4× samples remain at or below the stored peak, so an interpolated-only screen reports **no over** even though the analytic sine's between-sample peak exceeds full-scale. The test explicitly reproduces this miss; it then requires `high_frequency_near_ceiling_ambiguity_risk=true` and CLI `--fail-on-risk` exit 2. Control cases at low amplitude, low frequency, and stereo single-channel exercise specificity. A short (<16-frame) untestable file likewise fails closed with `technical_review_required=true`. The heuristic only reduces known false-negative risk; its thresholds are conservative and not calibrated as an ITU true-peak detector.

## Unscreened playback-edge admission

The centered sixteen-frame FIR emits interpolated phases only when it has samples on both sides. A file with hot values only at its opening or closing edge can therefore appear to have no estimated intersample over even though its edge is not fully reconstructed. `edge_interpolation_ambiguity_risk` separately marks >=95%-FS PCM in the first or final eight frames; `--fail-on-risk` returns 2, preserving the distinction between 'risk due to missing filter context' and an actually estimated over. Four synthetic tests cover hot start, hot end, stereo single-channel edge and an equally hot isolated **interior** impulse with quiet boundaries that must not trigger the edge warning. This check is deliberately conservative: it does not emulate a playback DAC, splice or outside-clip context, and it does not prove an audible defect.

## Signed PCM16 rail values

PCM16 stores **-32,768** and **+32,767** as the extreme negative/positive discrete samples. Reaching either rail does not mathematically prove a limiter clipped the signal, but in an A/B technical screen it should not silently clear. `full_scale_pcm_samples` is a count across all channels (no sample locations) and `full_scale_pcm_risk` is a distinct warning, included in `technical_review_required` / `--fail-on-risk`. Three synthetic tests check both signed rails, a nearby legal - but non-rail - value, and stereo one-channel saturation without path disclosure.

## Improved finite interpolation: 16 taps

An independent synthetic sine oracle exposed an additional false-negative of the earlier 8-tap filter: a legal-valued 0.25 cycles/sample PCM sequence from an ideal sine of amplitude 33,000 (slightly above full scale) and phase π/4 had reconstructed peak around **32,273**, so the 8-tap checker would miss a real theoretical over. The updated symmetric **16-tap** normalized Blackman-sinc 4× reconstruction estimates approximately **33,008** instead, flagging `intersample_over_risk`. Four extra deterministic regressions test the recovered positive case, a safe lower-amplitude control, minimum 16-frame eligibility, and FIR coefficient shape/DC gain.

This increases CPU cost, not the 32MiB/2M-frame per-source limit, 8M-frame group limit, file descriptors or streaming read bounds. A sixteen-frame ring remains constant-memory. The dedicated hosted maximum-capacity stress test is green at the current 16-tap source state (see the exact-run evidence above); later source changes require another immutable run before acceptance. The near-Nyquist counterexample at 0.4 cycles/sample can still evade finite FIR reconstruction and **must retain an explicit ambiguity warning**; no certified dBTP or musical quality claim is made.

## Independent analytic sine grid (new regression)

`tests/test_quality_intersample_oracle.py` synthesizes 256-frame, strictly local, mono PCM16 clips in a temporary directory from a known analytic single-frequency sinusoid. Ten normalized frequencies (0.05–0.48 cycles/sample), five amplitudes greater than one full scale, and 64 phases each are attempted; only cases whose **stored** PCM16 samples all remain legal are admitted to this golden oracle. The exact eligible subset is computed during CI; each has a mathematically known over-full-scale continuous sine peak, even where a finite screen may miss the over. The report prints aggregate counts of cases requiring review versus still uncleared, and the CI asserts only a **99% characterization floor**, not certified true-peak accuracy. A separate 80-case, lower-amplitude negative-control grid must not produce spurious alerts. Synthetic files are deleted on test completion and never uploaded. This is diagnostic evidence on intentionally artificial tones, not evidence of performance across real music, and `technical_review_required=false` still does not guarantee safe playback. CI executes the oracle on both the ordinary hosted Python interpreter and hosted Python 3.14.

## Adaptive extra phases and worst-case CPU admission (follow-up)

The 16-tap fourfold base grid missed eight marginal analytic sinusoids in the 360-case positive oracle because the true positive peak fell **between** the 4× sub-sample phases. Rather than running a more expensive 8× scan everywhere, each sixteen-frame interpolation neighborhood first computes 4× phases (¼, ½, ¾). If the maximum reconstructed magnitude reaches at least **97% full scale**, it also evaluates four interleaved 8× phases (⅛, ⅜, ⅝, ⅞), without another disk read. `adaptive_8x_refined_windows` reports only a count, not private sample positions. Quiet audio leaves the extra branch inactive. A 0.25-cycles/sample sine with 33,000 analytic amplitude and π/16 phase is a deterministic test where the 4× estimate is around 32,369 but the interleaved phase rises above 33,000. This refinement does **not** erase the near-Nyquist attenuation caveat, certify true peak, or imply anything about DJ preference.

The analytic oracle regression now requires >=99% of its **admitted** known-overs cases to request review, with 80 legal lower-amplitude negative controls producing no review warning; that is a bounded synthetic characterization floor, not a population statistic or certified audio-safety guarantee. CI adds a *second* maximum-capacity 2M-frame 48kHz stereo A/B test of constant legal 32,600 PCM amplitude. In this deliberately pessimistic CPU fixture every window activates the extra phases. Both 2M-frame stress cases enforce **<192MiB RSS** and report actual elapsed seconds on GitHub-hosted runners. The original 4× 16-tap run #39020818198 precedes adaptive refinement and cannot prove the new CPU worst case. Exact-head two-scenario CI remains authoritative.

## A/B pathname replacement race rejected (QA hardening)

Earlier versions held each WAV file descriptor open through the A/B scan, and correctly checked its unchanged inode, size and timestamps. However, a filesystem actor could rename or replace the **pathname** (including with an identical-length WAV, or a symlink) while the old descriptor remained open: the reader would continue scanning the original bytes and print a successful anonymous report for a pathname that no longer referenced those bytes. The reader now retains each original source pathname only in process memory and, **after scanning all inputs but before releasing any report**, compares a no-follow `os.stat()` of each pathname against the already-checked descriptor identity (device, inode, size, mtime and ctime). Missing/replaced/symlinked paths cause a generic `AudioInputError` with no private path in the message; the CLI emits its existing redacted exit-3 diagnostic. This is a bounded best-effort provenance check, not an atomic transaction across a hostile mutable filesystem, and not proof of ownership or legal permission.

Seven new deterministic synthetic regressions inject a path swap during baseline scanning, a candidate swap while the baseline is being read, source unlink, a symlink replacement, an unchanged distinct-file control, a redacted CLI exit-3 path-swap failure, and a Linux twelve-iteration descriptor-leak check. Every fixture is local temporary PCM16 silence; no real audio, extra network dependency or new VPS workload is involved. The verification adds metadata-only checks, not another PCM read. **Earlier CI success at `ada74c2` predates this change**; acceptance requires fresh green exact-HEAD quality, oracle, 2× max-capacity stress and Python 3.14 jobs.

### Acceptance for current safety regression

The new path-stability tests use deterministic `unittest.mock.patch` of the local private-stream scan only: they move a temporary baseline/candidate pathname after the file descriptor is already open, without uploading any audio. The production CLI must refuse a swapped input with exit 3, **without printing a JSON report or a private filename**, and repeated failures must close descriptors (verified by a Linux `/proc/self/fd` count). This tests actual behavior rather than just the presence of a pathname check. The new regression increases focused tests from **33 to 40**. The expensive two 2M-frame stereo CI resource scenarios, analytic sine oracle, and Python 3.14 replay must be revalidated on the final commit; earlier green runs are superseded.
